# Phase-five measurement notes

Use `docs/benchmarks/phase5` JSON for exact samples and `STATUS.md` for the comparison table. Desktop uses the official Godot 4.7.2 runtime; Android uses emulator-5554 / LittleGod_Test, API 35 x86_64, a host RTX 4070 Laptop GPU and Compatibility rendering. No physical Android device was connected.

Measurements distinguish simulation CPU, terrain/prop rebuilds, frame intervals, draw calls, engine static/video memory, and first engine frame. First engine frame is measured from engine process timing, not tap-to-interactive OS cold startup. The host launch-to-report value also includes the configured sampling duration and polling. No claim of phone thermals, power consumption or battery life follows from the 30-FPS setting.

The 0.4 pipeline fixed blocking restore by slicing work across frames, removed unused demo-world generation at boot and retained unchanged prop sprites. Phase five adds bounded state histories and local interactions. Spring adjacency now builds its extra spatial index only when a raised mountain exists. The early headless 0.5 offline sample was 294.805 ms for 480 ticks; a later lazy-index sample was 212.052 ms, with frame slices peaking at 4.414 ms. Different sample conditions mean this is directional evidence. Extra simulation still costs more than the 0.4 161.404-ms sample; wall-clock replay includes yields rather than blocking the interface.

The first final 0.5 emulator smooth sample was 20.99 FPS / 69.10-ms p95 over 30 seconds, with 1.547-ms average simulation and 19.473-ms last terrain rebuild. Battery saver was 28.47 FPS / 51.37-ms p95. A blank, zero-draw-call control reached only 50.25 FPS / 35.05-ms p95, and the preserved 0.4 build rerun in the same session reached 19.19 FPS / 75.88-ms p95. That weakens a claim that the added stories alone caused the slowdown, while confirming this environment did not meet the smooth target. Both slow samples are retained. Host read-only sampling showed external power, GPU around 65°C and modest CPU usage; those observations do not establish a single cause.

The emulator was rebooted without clearing the player package. Boot exceeded the initial 45-second polling timeout and completed at about 55 seconds. Subsequent profile samples are saved separately under `after-restart` rather than replacing the slow results. Every completed player-package benchmark compares the saved planet's bytes before and after. The disposable QA package alone may be cleared/reinstalled for isolated tests.

One 1024×1024 art atlas is retained. Silver creatures reuse the atlas through a shared shader rather than allocating new texture sheets. Weather, water, springs, hearts, banners and power effects use existing shaders/procedural graphics; low-quality mode reduces their counts. Creature simulation runs on the existing two-second tick, capped at 70 normal individuals. Offline steps cap at 480; histories cap at 64 cards and 128 deduplication IDs.

Engine/Forge shutdown can still emit ObjectDB/resource cleanup warnings. Android cached-shader reload warnings and occasional startup/process spikes remain visible in logs. These are not hidden by the benchmark harness. Sustained mid-range-phone performance remains a physical-device release gate.

Back navigation follows Godot's [quit-on-back setting](https://docs.godotengine.org/en/4.6/classes/class_projectsettings.html#class-projectsettings-property-application-config-quit-on-go-back) and [window Back signal](https://docs.godotengine.org/en/4.6/classes/class_window.html#class-window-signal-go-back-requested). PNG export uses the documented [native FileDialog](https://docs.godotengine.org/en/4.6/classes/class_filedialog.html#class-filedialog-property-use-native-dialog); Android native dialogs need API 29+ and filesystem access mode, without requesting unrestricted storage permission.

Final 720-wide Android measurements: 30.73 FPS / 51.52-ms p95 smooth, 29.87 / 47.03 saver, and 26.19 / 59.87 at 70 creatures. The final Android render was visually inspected. Video memory fell from 35.84 MB to 22.85 MB; smooth retains full effects. The target remains unmet. Desktop measured 60.06 FPS / 16.81-ms p95. Full VM restart preserved player-save bytes but did not restore the earlier emulator performance.
