The supplied `openko_example.png` was inspected as a repository screenshot, not a live runtime test.

## Scope and confidence

[README](https://github.com/Open-KO/KnightOnline/blob/7d6cf81093e142c928c2ac9510512b2b182178b5/README.md) targets old Knight Online 1.298/1299 and has both client and server source. Windows builds include the DirectX client and tools; cross-platform support is server-only. It expressly warns that the project is early, incomplete and not usable as a real production server. Its overview warning mentions upgrades as incomplete, while the current snapshot demonstrably contains normal item-upgrade implementation and tests. Therefore assess feature by feature, rather than treating either the warning or a class name as proof of complete support.

This is a better direct reference for the user's **Knight-style inventory/skills/combat interaction** than SandalCore. It is not a ready Godot/Android project, and it is not authoritative evidence for modern KO rebirth, high-level equipment, current drop rates or live-server balance.

## Important limits found in actual code

1. **Accessories are not a ready module:** `CUser::ItemUpgradeAccesories` has an empty body; `UIUpgradeSelect.cpp` comments out the ring-upgrade include. Do not claim complete accessory combination based on the menu.
2. **Modern rebirth is not established:** no rebirth/reverse implementation was found in the inspected normal-upgrade client/server/test path. The target version is old. Our existing +21 rebirth system remains LittleGod's adaptation, not something this repo validates.
3. **Siege class is not a completed territory war:** `KnightsSiegeWar.cpp` only initializes castle/master fields in its constructor at this snapshot. Other server battle code does not turn that file into proof of a ready player-region siege system. LittleGod still needs its own server-owned battle sessions and reward transactions.
4. **Do not copy rates from table fields blindly:** normal upgrade compares `GenRate` to a nested random draw `myrand(0, myrand(9000, 10000))`; a nearby comment questions its behavior. A table field divided by 100 is not automatically the actual probability of that implementation, still less a modern official server rate. Test fixtures are not verified current production data.
5. **Do not import destructive upgrade failure silently:** this normal-upgrade code clears the source item on a failed roll. LittleGod currently retains item and level while consuming ingredients. Copying the old behavior would change the user's economy and existing tests materially.
6. **Server assets are not a complete mobile art collection:** the checked-in `assets` tree has server map/event files, including SMD and EVT. It is not a freely reusable complete wardrobe, skill-animation, texture and mobile HUD pack. File presence alone establishes neither portability nor asset redistribution rights.
7. **Old architecture is a reference, not our replacement:** a large mutable `User.cpp`, binary client/server packets and a DirectX-specific presentation layer should not be ported wholesale into our Godot/GDScript and existing C# service.

## License/provenance boundary

The repository's [LICENSE](https://github.com/Open-KO/KnightOnline/blob/7d6cf81093e142c928c2ac9510512b2b182178b5/LICENSE) states MIT, including preservation of copyright/permission notices. The README also describes starting from original leaked source. Those are material facts for any direct reuse review; the root license label alone is not verification of the rights to every original game asset or historical source component. This review does not determine that provenance or change LittleGod's license. No code/assets have been copied into the game. Prefer original implementation/art from independently specified behavior until any intended direct reuse has been assessed at the specific-file level.

## How the three references should be used together

- **KO wiki / KO Bugda:** item-family vocabulary, displayed properties, desired progression/loot/quest patterns; verify missing/conflicting values instead of inventing them.
- **OpenKO:** concrete legacy KO interaction and client/server mechanics, equipment attachment architecture, spell target rules and transaction validation.
- **SandalCore:** clearer separations for ability results, NPC perception/leash, resource-node lifecycle and interest-based update design.
- **LittleGod:** original colony/creature-worker story, mobile controls, resource economy, save ownership, existing region/boss progress and our own tested balance.

Recommended next work remains **a complete original first-region NPC chain → distinct skill/effect/element rules → layered equipment animation → item-family expansion with measured balance → server-authoritative social/territory progression**. Reference study should improve these deliverables rather than restart the project or add unsupported systems merely to match a legacy menu.
